# Разработка MVP интернет-магазина с ролевой моделью доступа (Vue 3 + Strapi)

## 1. Главная цель задачи
Закрепить навыки проектирования SPA-приложений средней сложности, работы с асинхронным стейтом, типизацией и ролевой моделью авторизации (RBAC). Продемонстрировать навыки самостоятельной интеграции фронтенда с Headless CMS и построения чистой архитектуры на Vue 3.

---

## 2. Технический стек проекта
* **Frontend:** Vue 3 (Composition API, `<script setup>`), TypeScript, Pinia, Vue Router.
* **Backend:** Headless CMS Strapi (REST API, плагин Users & Permissions).

---

## 3. Декомпозиция задачи и этапы реализации

### **Этап 1: Проектирование бэкенда (Strapi CMS)**
* Развернуть Strapi локально или в Docker.
* Создать типы контента (Collection Types): `Products` (название, цена, описание, изображение, количество) и `Categories`.
* Настроить стандартные роли в плагине Users & Permissions: **Authenticated** (для обычных пользователей) и создать кастомную роль/флаг для **Admin**. Настроить права доступа к API для каждой роли.

### **Этап 2: Архитектура и Базовый функционал Frontend**
* Инициализировать проект (рекомендуется использовать Vite + TS) и настроить линтеры (ESLint/Prettier).
* Организовать структуру папок по методологии **Feature-Sliced Design (FSD)**:
  * `app/` — инициализация приложения (роутер, стор, стили, провайдеры).
  * `pages/` — страницы приложения (каталог, авторизация, корзина, ЛК, админка).
  * `widgets/` — крупные самостоятельные блоки интерфейса (хедер, сетка товаров, карточка корзины).
  * `features/` — интерактивный функционал/сценарии (добавление в корзину, авторизация, фильтрация).
  * `entities/` — бизнес-сущности (продукт, пользователь, корзина) со своими сторами, типами и простыми UI-компонентами.
  * `shared/` — переиспользуемый инфраструктурный код (UI-kit, API-клиенты, хелперы, типы).
* Реализовать адаптивную верстку каталога товаров с возможностью фильтрации по категориям.

### **Этап 3: Система авторизации и Ролевая модель**
* Создать страницы **Входа** и **Регистрации** с валидацией полей.
* Реализовать `auth.store` на Pinia для хранения JWT-токена, данных текущего пользователя и его роли.
* Настроить Vue Router и защитить приватные маршруты с помощью Navigation Guards (`beforeEach`).

> **Логика доступов:**
> * **Гость:** Видит только каталог, вход и регистрацию. При попытке зайти в ЛК — редирект на Login.
> * **Пользователь (User):** Имеет доступ к каталогу и Личному кабинету (профиль, управление корзиной).
> * **Администратор (Admin):** Имеет доступ ко всему функционалу + защищенной Админ-панели.

### **Этап 4: Личный кабинет и корзина (Роль: User)**
* Реализовать `cart.store` (Pinia) для добавления товаров в корзину и подсчета итоговой стоимости.
* Создать страницу Личного кабинета с выводом информации о текущем пользователе.

### **Этап 5: Панель управления каталогом (Роль: Admin)**
* Создать интерфейс Админ-панели (выделенный layout или отдельный роут).
* Реализовать полноценный **CRUD** для товаров: добавление нового товара (с загрузкой картинки в Strapi), редактирование текущих позиций и удаление.

---

## 4. Критерии успешности (Definition of Done)
* **Архитектура (FSD):** Строгое соблюдение методологии Feature-Sliced Design. Запрещены сквозные кросс-импорты между слайсами одного уровня (например, фича не должна импортировать другую фичу). Все внешние импорты из слайсов должны осуществляться строго через Public API (`index.ts`).
* **TypeScript:** Полное отсутствие `any`. Все ответы от Strapi API, стейты сторов и пропсы компонентов строго типизированы через `interface` или `type`.
* **State Management:** Логика авторизации и корзины полностью вынесена в Pinia (в рамках соответствующих слайсов `entities` или `features`). Компоненты остаются «глупыми» (отвечают только за отображение и вызов экшенов).
* **Безопасность:** Прямой ввод URL админки или ЛК неавторизованным пользователем (или юзером без роли Admin) корректно обрабатывается роутером (редирект на 403 страницу или форму логина).
* **UX/UI:** Наличие лоадеров (спиннеров) во время ожидания ответов от API и понятная обработка ошибок (например, уведомление «Неверный логин или пароль»).

## 5. Что этот проект развивает (Ценность для компании)
* Глубокое понимание жизненного цикла Vue-компонентов и реактивности в Composition API.
* Навык работы с продвинутыми фичами Vue Router (динамические мета-поля, middleware/guards).
* Понимание принципов клиент-серверного взаимодействия и авторизации на базе JWT.
